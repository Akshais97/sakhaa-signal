## Anti-Patterns Verdict

Does this look AI-generated? **Yes — within the first second.** It is a textbook "neuromarketing sci-fi HUD," which is precisely the aesthetic the project's own brand guidelines forbid.

### LLM assessment

- **Aesthetic family is the AI-slop default for "AI video tool":** dark graphite canvas, violet/indigo gradients, animated grid background, scanline, blurred aurora blobs, neon glow shadows, a fake terminal with blinking cursor, matrix-style "DecryptedText" scramble, count-up numbers, and a mouse-follow spotlight card. Five decorative motion systems run simultaneously on load.
- **Emoji-as-icons everywhere** (17 emoji in `CLUSTER_METADATA` alone, plus ✨ 📊 ⚡ 🖥️ 🎬 📁 🚨 🖼️ 🎥 🚀 ☁️ 💎 🤝 📥 ⚙️ 📋 ✅ 💡 👉 ▶). The strongest "AI made that" tell, inconsistent across platforms.
- **Hero-metric template:** four circular gauges (EP / VP / CS / BR) with big % + label + "Index" tag + colored ring, repeated three times (job cards, dashboard sidebar, results page). SaaS cliché.
- **Gradient text:** `.shiny-text` uses `background-clip: text` on a sweeping gradient, used on the primary "Export Outcomes" button. Explicitly banned.
- **Gradient buttons:** `from-indigo-600 to-violet-600` (New Creative Analysis), `from-indigo-500 to-purple-500` (upload progress), tri-color Iris→Ember→Iris accent line on login.
- **Glassmorphism as default:** `backdrop-blur-md`/`-lg` on header, footer, sidebar, login card, and every static-report panel — decorative.
- **Identical card grids:** jobs (2-col identical), dials (2×2 / 4 identical), cluster rows identical.
- **Pure black:** `bg-black/75`–`/80` modal scrims and `bg-black/35` error overlay (detector flagged 3).
- **No personality earned through craft** — personality is borrowed from "neon terminal" clichés instead of the brand's own concept (the 9:16 frame + one Ember spark).

### What the detector missed (LLM caught, scanner couldn't)

The detector only matches Tailwind utility patterns; it cannot see custom CSS classes or inline structure. It therefore missed the largest issues:

- `.shiny-text` gradient text (`globals.css:276`) — lives in a custom class, not a utility.
- Emoji-as-icons (content, not class).
- Sub-14px text sizes (`text-[7px]`…`text-[11px]`) — the most pervasive accessibility failure.
- The **two-system split**: `SignalJobWizard.tsx` + `static-report.tsx` use raw Tailwind `slate`/`indigo`/`emerald`/`rose` defaults, completely ignoring the graphite/iris token system the rest of the app uses.
- Glassmorphism (`backdrop-blur-*`) and the sci-fi HUD layer stack.
- Fake hardcoded metrics on every completed job card.
- Wrong fonts (Outfit + Inter instead of Clash Display + Satoshi).
- Neuroscience/brain-response claim violations.

No detector false positives — all 7 findings are real.

## Overall Impression

There is a genuine product concept buried in here — a "studio instrument" for short-form creative, with an honest 9:16-frame mark and a single Ember spark, a claim boundary that admits "directional, not predictive," and a real status pipeline. The footer copy is on-brand.

But the chrome around it is the opposite of what the brand demands: a neon sci-fi HUD wrapped in two inconsistent design systems, talking in neuroscience jargon the user doesn't speak, showing fake numbers as if they were measured, at text sizes nobody can read. The single biggest opportunity: **strip the sci-fi HUD, collapse to one token system, and let the honest studio-instrument concept come through.** The brand book already tells you exactly what this should look like — the app just isn't following it.

---

## What's Working

1. **The 9:16 frame + Ember spark mark is a strong, ownable concept** (header, login, job-wizard dropzone, results preview). It is the one piece of genuine brand identity, and it is used consistently as a motif. Keep this; build outward from it.
2. **Status pipeline communication is genuinely decent** — progress percentage, friendly state labels, a vertical stepper, and the `unknown` diagonal-hatch treatment preserve "unknown" as a real state. The status-vocabulary intent aligns with the content guide.
3. **Honest footer disclaimers** ("Assists production using research-prior indices; directional, not predictive." / "Built using structural patterns observed in high-performing short-form content. Assists production; performance outcomes are not guaranteed.") are verbatim approved phrases from the content guide §10. The intent is right — it is the rest of the UI that contradicts them.

## Priority Issues

### [P0] Two incompatible design systems in one app
- **Why it matters:** `SignalJobWizard.tsx` and `static-report.tsx` are built on raw Tailwind `slate-950`/`indigo-500`/`emerald`/`rose` defaults with `rounded-2xl`, while the dashboard, login, JobWizard, and results use the graphite/iris/ember token system with `rounded`. The same "primary action" is a graphite `bg-iris-primary` pill in one place and an `indigo-600` `rounded-xl` block in another. A user moving from the dashboard to "New Creative Analysis" or to a static report crosses into a different product. This is the product-register cardinal sin: if the save button looks different in two places, one is wrong.
- **Fix:** Pick the graphite/iris/ember token system (it is the one `globals.css` documents and the brand book endorses). Rewrite `SignalJobWizard.tsx` and `static-report.tsx` to use `--surface-*`, `--text-*`, `--border-*`, `--interactive-primary-bg`, and the `.bg-graphite-*` / `.iris-primary` / `.ember-creative` helpers. One radius scale (define `--radius-*` tokens), one button shape, one form-control vocabulary.
- **Suggested command:** `/impeccable polish` (design-system alignment is the core of polish).

### [P0] Sci-fi HUD layer stack directly violates the brand book
- **Why it matters:** `PROJECT_BRAND_GUIDELINES.md` §7: *"Avoid AI-cliché aesthetics: no neon-grid 'AI brain' imagery, no glowing blue circuitry… The look is a colourist's suite, not a sci-fi HUD."* This app is exactly the sci-fi HUD: `dashboard-canvas` animated grid-pan + scanline, `soft-aurora-ambient` blurred blobs, neon `shadow-[0_0_20px_rgba(…)]` glows, a fake "GPU Worker Process Logs" terminal with blinking `$ tribev2-pipeline --run` cursor, "Vast.ai GPU Worker Connected" with `animate-ping`, `DecryptedText` matrix scramble, `CountUp`, and `SpotlightCard`. None of this conveys state; all of it is decoration that fights the content.
- **Fix:** Remove `grid-pan`, `scanline`, the aurora blobs, the neon glow shadows, `DecryptedText`, `CountUp`, and `SpotlightCard`. Keep a single calm graphite canvas (the brand's "studio surround"). If a terminal log is real, show real logs plainly; if it is not, do not fabricate "[RUN] Executing…" strings client-side. Replace "Vast.ai GPU Worker Connected" theater with the actual status.
- **Suggested command:** `/impeccable quieter` then `/impeccable polish`.

### [P0] Sub-14px text across the entire product (accessibility + brand violation)
- **Why it matters:** Brand §4: "Body text never sets below 16px in marketing or 14px for anything actionable in product." The app runs on `text-[7px]`, `text-[8px]`, `text-[9px]`, `text-[10px]`, `text-[11px]`. Job IDs, status pills, labels, cluster descriptions, footer, the "9:16" mark label, timeline legends — most of the readable surface is 9–11px. This fails WCAG, fails the brand floor, and is the single most pervasive craft failure. It also fails Sam (low-vision) and Casey (mobile) personas outright.
- **Fix:** Establish a fixed rem type scale (per product.md: 1.125–1.2 ratio). Floor: 14px for labels/metadata, 16px for body, larger for headings. Replace every `text-[7/8/9/10/11px]` with the scale. Use JetBrains Mono only for IDs, hashes, timestamps, counts — not for labels and body.
- **Suggested command:** `/impeccable typeset`.

### [P1] Fake metrics presented as measured results
- **Why it matters:** Every "COMPLETED" job card shows hardcoded `~82% / ~74% / ~88% / ~65%` for EP/VP/CS/BR — identical for every job, not real data. Brand §7: *"Never mock up dashboards showing invented numbers."* The results page falls back to `MOCK_SCORES`/`MOCK_LLM_REPORT` silently when a fetch fails, so a user can be staring at demo numbers without knowing. This is the Riley persona red flag: "features that appear to work but silently produce wrong results," and it contradicts the brand's central honesty promise.
- **Fix:** Never show scores for a job that has none. On the dashboard card, show "Ready" + a link to the report — not fabricated indices. In results, if scores are missing, show an honest empty/error state, not `MOCK_SCORES`. Reserve the demo data for an explicit `/results/demo` route labelled as a sample.
- **Suggested command:** `/impeccable harden`.

### [P1] Neuroscience / brain-response claims the brand forbids
- **Why it matters:** The UI is saturated with claims the brand book §6.1 bans: "Neuromarketing Brain-Response Creative Intelligence," "Predictive Biometric Outcomes," "Calibrated directly from parcellated EEG & attention trace profiles," "HCP-MMP1 Cortical Areas," "Limbic/amygdala activation," "fusiform and parahippocampal," "prefrontal cortex value coding," "Brain Networks (A-Q)." The content guide §10 prohibits "measures attention or emotion," "scientifically proven," and predictive language. The honest footer disclaimers cannot carry the weight of a UI that otherwise claims to read brains.
- **Fix:** Reframe to research-prior, directional language the content guide approves: "research-prior indices; directional, not predictive," "observed patterns," "assists production; outcomes are not guaranteed." Drop "biometric," "EEG," "brain-response," "predictive," and the per-cluster anatomical claims from the UI chrome (keep them out of the marketing surface entirely per brand §3.3/§6). This is copy work, not a product-concept rewrite — the underlying indices can stay; the claim framing must become honest.
- **Suggested command:** `/impeccable clarify`.

### [P1] Emoji-as-icons across every surface
- **Why it matters:** Emoji icons render inconsistently across platforms, carry no brand identity, read as unprofessional, and are the loudest "AI made that" signal. They also break Sam (screen-reader) — `👁️👤🧠🔥` announce as literal emoji names. The brand has a real mark (9:16 + spark) but no icon system, so emoji fill the vacuum.
- **Fix:** Introduce one icon set drawn from the design system (monochrome, current-color stroke, 16/20/24px). Replace all decorative emoji. Keep no emoji in labels/buttons (remove ✨ from CTAs — content guide bans "Magic"-adjacent sparkle hype).
- **Suggested command:** `/impeccable polish`.

### [P2] Wrong fonts loaded
- **Why it matters:** `layout.tsx` loads **Outfit + Inter + JetBrains Mono** via `next/font/google`. The brand book §4 mandates **Clash Display** (display) + **Satoshi** (UI/body) + **JetBrains Mono** (data). `globals.css` even declares `--font-display: "Clash Display","Satoshi"` but `next/font` overrides `--font-display` with Outfit, so Clash/Satoshi never load. The app is set in the wrong typeface family.
- **Fix:** Load Clash Display + Satoshi (Fontshare / Indian Type Foundry, the brand's India-grounded choice) and wire `--font-display`/`--font-text`/`--font-mono` correctly. Keep JetBrains Mono for data only.
- **Suggested command:** `/impeccable typeset`.

### [P2] Status colors used decoratively; meaning carried by color alone
- **Why it matters:** Brand §3.3: status colors (cyan/green/amber/coral/violet) "must not be used decoratively." They are used as the primary palette — cyan VP dial, amber BR dial, coral error, green success — and as neon glows. Cluster "Strong" (ember) vs "Muted" (graphite) and rule PASS/FAIL (green/red) convey meaning by color alone, failing Sam.
- **Fix:** Status colors only on status indicators. Add a text label or icon to every color-coded state ("Strong"/"Muted" already exist — keep them; add them where missing, e.g. PASS/FAIL). Move dials to Iris (the one brand color) with the status system reserved for actual status.
- **Suggested command:** `/impeccable colorize` then `/impeccable polish`.

### [P3] Naming, copy, and motion hygiene
- Two product names ("Sakhaa Forge" header vs "TribeV2 Ad Scorer" title/login vs "Sakhaa Forge Neuromarketing Pipeline Studio" footer) — brand §1.1 says one name. Title Case headings ("Scoring Job Repository", "Creative Optimization Recommendations", "Areas for Optimization") violate sentence-case rule. Em dash in the `<title>`. No `prefers-reduced-motion` on any of the five motion systems. Custom scrollbars reinvent a standard affordance. Aggressive 1s/3s polling. `window.location.href` full reload after job creation.
- **Suggested command:** `/impeccable clarify` + `/impeccable polish`.

## Persona Red Flags

### Alex (Power User) — dashboard/admin
- No keyboard shortcuts anywhere; primary "New Creative Analysis" action requires a mouse click into a modal.
- Modals (`JobWizard`, `SignalJobWizard`) have no Esc-to-close; the only exit is the × or Cancel button.
- One-job-at-a-time; no bulk select, batch re-run, or multi-select on the repository grid.
- Full `window.location.href` reload after creating a job — Alex loses SPA state and waits for a fresh load.
- The 1s and 3s polling intervals will irritate Alex on a large repository; no way to pause refresh while reading a report.

### Sam (Accessibility-dependent) — dashboard/admin
- Most text is 7–11px, far below 14px; screen-magnification users still hit sub-readable sizes, and low-vision users cannot read job IDs, status pills, or cluster descriptions at all.
- Outcome/cluster meanings appear only on `group-hover:block` — invisible to keyboard and screen readers; the tooltip text isn't in the a11y tree.
- Meaning carried by color alone: cluster Strong/Muted, rule PASS/FAIL, status pills.
- Emoji icons announce as literal emoji names ("brain emoji, fire emoji") to a screen reader.
- No `prefers-reduced-motion` — the grid-pan, scanline, aurora, blinking cursor, count-up, and matrix scramble all force themselves on reduced-motion users.
- Close/back buttons are bare glyphs (`&times;`, `←`) without `aria-label`.

### Jordan (First-Timer) — also relevant (creation wizard)
- The wizard is full of jargon a first-timer cannot parse: "TribeV2 3D-ResNet," "Wav2Vec audio encoder," "fused sequence tensor shape [1, 240, 1024]," "HCP-MMP1," "17 A-Q cognitive clusters." Jordan abandons at mode-select.
- No contextual help at the mode-selection decision point — three modes with no guidance on which to pick beyond a one-line subtitle.
- After upload, fabricated terminal logs ("[RUN] Executing TribeV2 attention transformer model...") look authoritative but convey nothing Jordan can act on.

## Minor Observations

- `.unknown-diagonal-hatch` correctly preserves `unknown` as a real state — keep this; it is the one piece of status design that follows the content guide.
- Login uses an inline hand-drawn Google "G" SVG — fine, but the card's tri-color Iris→Ember→Iris top accent line is a decorative gradient that the brand's "Ember spent once" rule would push back on.
- `globals.css` carries ~150 lines of imported "premium animation" CSS (`.shiny-text`, `.spotlight-card`, `.soft-aurora-*`, `.aurora-blob`) that nothing in the brand system calls for — dead-weight drift.
- Job card shows "Mode: c_both / Full" — raw internal codes leaked into the UI; content guide says use canonical terms, not codes.
- `text-graphite-*` / `bg-graphite-*` helper classes are a good idea but only ~40% adopted; the rest is raw hex.
- `getProgressPercentage` returns 100% for FAILED/CANCELLED — a failed job showing a full progress bar misleads.
- Results page "Arousal & Attention Timeline Trace" is a static hardcoded SVG path, not real data — another silent fake.

## Questions to Consider

- What if the dashboard dropped the terminal/grid/aurora theater entirely and read as a calm graphite studio console — would the product feel more or less credible to a paying brand?
- The honest footer admits "directional, not predictive." Why does the rest of the UI then claim "predictive biometric outcomes" and "brain-response"? Which is the product you are actually shipping?
- If a user could not see color, would they still understand the status of every job? (Today: no.)
- What would a "confident, calm studio instrument" version of the results page look like — four honest indices with uncertainty bands and one recommended next edit, instead of a sci-fi HUD with 17 brain clusters?
