## Anti-Patterns Verdict

Does this look AI-generated? **Less than before, but still yes in the details.** The sci-fi HUD has been stripped, fonts are now correct, emoji are gone, and the two-system split is mostly healed. What remains are the quieter AI-slop tells: hero-metric circular dials, status colors sprayed as decoration, and a wall of neuroscience jargon that reads like an LLM hallucinated a brain-scanning product.

### LLM assessment

- **Hero-metric template survives intact:** four circular gauges (EP / VP / CS / BR) with big % + small label + "Index" tag + colored ring on `results/[jobId]`. This is the same SaaS cliché noted in the previous run.
- **Status colors used as the primary palette:** cyan VP dial/tag, amber BR dial/tag, green success/strong, red fail/error. These are semantic status colors per the brand book §3.3, but they are carrying decorative meaning in marketing-style score cards.
- **Neuroscience-as-credibility copy is pervasive:** login says "Neuromarketing creative studio" and "FAIR Meta TribeV2 digital brain mapping models"; dashboard says "Neuromarketing decision studio" and "predictive parcellation lineage"; results says "Predictive biometric outcomes" and "Calibrated directly from parcellated EEG and attention trace profiles"; cluster proxies cite occipital activation, fusiform/parahippocampal response, temporoparietal junction, limbic activation, anterior cingulate cortex. The brand book §6.1 and content guide §10 prohibit all of this.
- **Typography is now on-brand in family** (Clash Display + Satoshi + JetBrains Mono) **but off-brand in execution:** headings are set `tracking-tight` and visually run together ("Createscoringjob" in the legacy wizard); multiple labels, tags and IDs sit below the 14 px actionable floor.
- **No decorative emoji, no neon grid, no aurora, no fake terminal logs:** these have been removed. The 9:16 + Ember spark mark is consistent and ownable.

## Overall Impression

The 2026-07-31 polish pass fixed the loudest problems: the sci-fi HUD is gone, the fonts are right, emoji are gone, the two design systems have collapsed toward one graphite/iris vocabulary, and the dashboard no longer fabricates job-card metrics. That is genuine progress.

But the interface still cannot ship because the product copy violates its own claim boundary at almost every turn. The UI presents itself as a neuromarketing brain-mapping predictor while the brand book and content guide explicitly forbid those claims. Until the language is reframed as research-prior, directional and non-predictive, the visual cleanup is undermined by the words. The second blocker is typography craft: the correct typefaces are loaded, but tight tracking and sub-13 px text make the UI feel machine-generated rather than intentionally typeset.

**Single biggest opportunity:** finish the `/impeccable clarify` pass on every user-facing string, then `/impeccable typeset` to fix tracking, scale and the 13 px floor.

## What's Working

1. **The sci-fi HUD has actually been removed.** `globals.css` no longer carries grid-pan, scanline, aurora blobs, neon glows, `DecryptedText`, `CountUp` or `SpotlightCard`. The dashboard reads as a calm graphite studio console. This is the most important improvement from the previous run.
2. **Inline SVG icon system.** Decorative emoji are gone and replaced with a small, monochrome, current-color inline icon set. The one brand mark (9:16 frame + Ember spark) is used consistently across header, login and wizards.
3. **No fabricated dashboard metrics.** Completed job cards no longer show hardcoded `~82% / ~74%` dials; they say "Report ready" and link to the report. Demo data is confined to the explicit `/results/demo` route.
4. **Design-system convergence.** `SignalJobWizard.tsx` and `static-report.tsx` now use `--surface-*`, `--text-*`, `--border-*` and `--interactive-primary-bg` tokens. The two-system split noted in the previous critique is substantially healed.

## Priority Issues

### [P0] Neuroscience / predictive claims still saturate the UI
- **Why it matters:** `PROJECT_BRAND_GUIDELINES.md` §6.1 and `PROJECT_CONTENT_AND_LANGUAGE_GUIDE.md` §10 prohibit "scientifically proven", "measures attention/emotion/brain response", predictive language and causal claims. The UI violates this on almost every surface. A paying India-first real-estate brand will interpret this as "this product reads brains and predicts performance," which the product does not do. This is a legal/brand red line, not a polish issue.
- **Fix:** Reframe every string to the approved vocabulary: "research-prior indices; directional, not predictive," "observed patterns," "assists production; outcomes are not guaranteed." Drop "neuromarketing," "HCP," "brain maps," "biometric," "EEG," "parcellated," "cortical," "predictive" and named anatomical regions from the UI chrome. Rename "17 cognitive clusters" to a neutral research-prior label. Update `CLUSTER_METADATA` proxies to plain behavioral proxies.
- **Seen in screenshots:** login page tagline, dashboard subtitle, results "Predictive biometric outcomes" heading, cluster descriptions, empty-state explainer.
- **Suggested command:** `/impeccable clarify`.

### [P0] Sub-13 px text and run-together headings undermine the new type system
- **Why it matters:** `PROJECT_BRAND_GUIDELINES.md` §4 states "Body text never sets below 16 px in marketing or 14 px for anything actionable in product." Screenshots show `text-xs` (13 px) tags like "VP index" / "BR index", status pills, IDs, wizard labels, metadata and the 9:16 mark label. In addition, `tracking-tight` on headings makes multi-word titles render as one visual mass (e.g., "Createscoringjob"). This fails the brand typography rules and the low-vision persona.
- **Fix:** Establish and enforce the type scale in `globals.css`: 14 px floor for actionable/labels, 16 px body, larger steps for headings. Remove `tracking-tight` from multi-word headings or add normal letter-spacing. Use JetBrains Mono only for IDs, hashes, timestamps and counts.
- **Suggested command:** `/impeccable typeset`.

### [P1] Status colors used decoratively in score cards and clusters
- **Why it matters:** Brand §3.3 says status colors (green/amber/red/cyan) "must not be used decoratively." In `results/[jobId]`, the VP dial and "VP index" tag are cyan, the BR dial and "BR index" tag are amber, strong clusters are Ember/amber, and PASS/FAIL rule badges are green/red. These colors carry semantic meaning from the status system and are being borrowed for score aesthetics.
- **Fix:** Use Iris (the brand primary) for all four outcome dials and their tags. Reserve status colors only for actual status indicators (job status, rule PASS/FAIL — but add text labels or icons so color is not the sole signal). Strong/muted cluster states should use a text label + one consistent bar color, not Ember/status green.
- **Suggested command:** `/impeccable colorize` then `/impeccable polish`.

### [P1] Product naming drift — "Sakhaa Signal" is not in the brand book
- **Why it matters:** Brand §1.1 defines V0 as **Sakhaa Forge** and V2 decision intelligence as **Sakhaa**. "Sakhaa Signal" appears nowhere in the brand system. The login title, dashboard header, results header and footer all use it. This creates a second product name inside one product.
- **Fix:** Decide if this surface is V0 (Sakhaa Forge) or the V2 decision layer (Sakhaa) and rename consistently. If "Signal" is an internal codename, remove it from customer-facing chrome.
- **Suggested command:** `/impeccable clarify`.

### [P2] Interaction hygiene: modal exits, keyboard support, full-page reload
- **Why it matters:** Modals (`JobWizard`, `SignalJobWizard`) have no Esc-to-close handler. The primary "New creative analysis" action requires a mouse click. After a Signal job is created the code does `window.location.href = /analysis/${jobId}`, losing SPA state. There are no keyboard shortcuts, no bulk select, no way to pause the 1 s / 3 s polling.
- **Fix:** Add `keydown` Esc handlers to modals. Convert the post-creation redirect to a `router.push` or inline state update. Add basic keyboard shortcuts (e.g., `n` for new analysis, `Esc` to close). Consider a pause-refresh toggle on the dashboard.
- **Suggested command:** `/impeccable harden`.

### [P2] Near-black card backgrounds flatten hierarchy
- **Why it matters:** `results/[jobId]` and the dashboard use `#0B0A09`, `#0C0B02` and `#121110` as card/panel backgrounds on a `#1A1815`–`#0B0A09` canvas. The contrast between surface and panel is too low, making cards feel like holes rather than raised objects. The detector also flagged `bg-black/30` in the error panel.
- **Fix:** Use the token surface system (`--surface-raised`, `--surface-sunken`) consistently. Ensure panel-to-canvas contrast is perceivable. Replace `bg-black/30` with the error-background token.
- **Suggested command:** `/impeccable colorize`.

## Persona Red Flags

### Alex (Power User) — dashboard/admin
- No keyboard shortcut to create a job; must click "New creative analysis."
- Modals cannot be closed with Esc; must hunt the × or Cancel button.
- Full `window.location.href` reload after creating a Signal job — Alex loses list scroll position and search/filter state.
- 1 s and 3 s polling intervals run continuously; no pause while reading a report.
- No bulk select, batch re-run or multi-select on the repository grid.

### Sam (Accessibility-dependent) — dashboard/admin
- Multiple text elements sit below 14 px: job IDs, status pills, "VP index" / "BR index" tags, wizard labels, the 9:16 mark label, footer metadata.
- Headings with `tracking-tight` run words together, reducing legibility for low-vision users and screen magnification.
- Cluster bars and rule PASS/FAIL badges convey meaning by color alone; the "Strong"/"Muted" labels help clusters but are still tiny.
- Status filter buttons use color (Iris) for selection state without an additional shape/aria marker, though `aria-pressed` is present.
- The timeline graph is a static SVG with no data table alternative.

### Jordan (First-Timer) — also relevant (creation wizard)
- The mode selector uses internal/provider terms: "Single image OCR, visual rules and GPT", "Video OCR, Groq STT, YAMNet and timeline", "GPU transformer, 17-cluster and neuro scores." Jordan cannot tell which mode to pick from those descriptions.
- The dashboard subtitle says "Neuromarketing creative tests and predictive parcellation lineage" — Jordan does not know what parcellation is.
- No contextual help at the mode decision point beyond a one-line subtitle.
- The results page promises "Predictive biometric outcomes" and "Calibrated directly from parcellated EEG," which sounds authoritative but is not what the product actually does.
